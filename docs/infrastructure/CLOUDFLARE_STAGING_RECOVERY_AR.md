# استعادة بيئة Staging عبر Cloudflare وSupabase

تاريخ التحقق: 25 أكتوبر 2026. هذا دليل تشغيل للبيئة المعزولة الخاصة بالاختبار؛ لا يستخدم إعدادات الإنتاج.

## نتيجة فحص الموارد

- مشروع Supabase المخصص للاختبار موجود مستقلًا: `edupro-school-erp-staging`، ومعرّف المشروع `vjcjscqgmijgzagshsca`.
- قائمة Hyperdrive في حساب Cloudflare احتوت إعدادين فقط: `schoolfor-manus-db` و`schoolfor-manus-admin-db`. إعداد `schoolfor-manus-db` متصل بمضيف Supabase مختلف عن مشروع Staging. لم يظهر إعداد Hyperdrive مستقل للاختبار.
- قائمة Workers لم تحتوِ عاملًا مستقلًا باسم `schoolfor-manus-staging`. يوجد ملف إعداد محلي `wrangler.staging.jsonc`، لكنه لا يضم Hyperdrive binding؛ وجود الملف لا يثبت وجود عامل منشور أو اتصال قاعدة.
- فحص بيئة GitHub السابقة لم يجد أسرار Staging. إعداد `production-database-migrations` خاص بالإنتاج، ولا يجوز إعادة استعمال أسراره في الاختبار.
- أُنشئت بيئة GitHub Actions باسم `staging`، وقُيّد استخدامها بفرع `codex/fees-module-repair` وحده حتى لا تصل فروع أخرى إلى أسرار الاختبار. لا تحتوي حاليًا على أسرار أو متغيرات. بعد نشر العامل، يوضع عنوان الفحص العام في متغير مستودع غير سري باسم `EDUPRO_STAGING_HEALTH_URL` كي يستمر فحص الجاهزية الدوري على الفرع الافتراضي دون منحه أسرار Staging.
- ملف `.env.staging` المحلي كان موجودًا، لكن مفاتيح الاتصال والمصادقة اللازمة فارغة. لم تُقرأ قيم أسرار الإنتاج ولم تُستخدم.

## إيقاف معاينات الفروع المتصلة بالإنتاج

- أظهر فحص Cloudflare أن معاينات Worker لم تكن معزولة: روابط إصدارات CI للفرع كانت جاهزة تحت خدمة `schoolfor-manus`، وروابط الإصدار تستخدم إعدادات وموارد Worker القائمة. إعداد الإنتاج كان يعلن `EDUPRO_ENVIRONMENT=production` ويفتح الكتابة المالية؛ لذلك لا يجوز استخدام روابط الإصدارات هذه لاختبار Staging.
- أُوقف إنشاء معاينات الفروع في إعداد Builds، وأُوقف عنوان Preview العام `*-schoolfor-manus.salafe10.workers.dev` مع إبقاء عنوان الإنتاج `schoolfor-manus.salafe10.workers.dev` ونطاق المدرسة فعّالين. بعد التغيير أعاد فحص HTTP/1.1 فشل TLS لعنواني معاينة الفرع والإصدار، بينما أعاد فحص صحة Worker الإنتاجي والموقع الأساسي HTTP 200.
- كان مشروع Pages يقبل جميع فروع Preview، وملف `functions/api/[[path]].ts` يمرر `/api/*` إلى Worker الإنتاجي. أُوقف النشر التلقائي لفروع Preview في Pages مع الإبقاء على نشر `master` الإنتاجي، وفُعّلت حماية Cloudflare Access لروابط Preview القائمة. يحتوي إعداد Preview في Pages على متغير البناء العام `BUN_VERSION` فقط ولا يحتوي روابط قاعدة أو bindings.
- يجب إبقاء معاينات Pages وWorker مغلقة إلى أن يُنشر Worker Staging مستقل وتُراجع وجهة API في معاينات Pages؛ إعادة فتحها قبل ذلك قد تعيد توجيه اختبارات الفرع إلى الإنتاج.
- أظهرت صفحة Worker أن خيار `Disable builds` للإنتاج مفعّل، بينما العامل والنطاق الإنتاجي يعملان. لم يتغير هذا الخيار في هذه الجولة؛ يلزم التحقق من نية مالك الحساب قبل تعديل إعداد النشر الآلي للإنتاج.

لم تُجرَ أي كتابة أو ترحيل على قاعدة Staging خلال هذا الفحص. Hyperdrive وWorkers الإنتاجية لم تُعدّل.

## تهيئة الملف المحلي بأمان

من جذر المستودع:

```powershell
npm run staging:prepare
```

ينشئ الأمر `.env.staging` من القالب إذا لم يكن الملف موجودًا، ويحافظ على أي ملف سابق دون استبداله. يقيّد صلاحيات Windows للمستخدم الحالي و`SYSTEM` و`Administrators`، أو يضبط صلاحية `0600` على الأنظمة الشبيهة بـUnix. الملف مستثنى من Git.

لإكمال الاتصال بعد تدوير كلمة مرور قاعدة Staging، شغّل النموذج المحلي:

```powershell
npm run staging:connect
```

افتح `http://127.0.0.1:4182/` وأدخل كلمة مرور `postgres` التي عيّنتها من لوحة مشروع `edupro-school-erp-staging`، ثم اختر كلمة مرور جديدة قوية لدور `edupro_staging_app` وأكدها. النموذج يتحقق من هوية المشروع وخصائص الدور، يحدّث كلمة مرور الدور المقيد، ثم يحفظ الملف المحلي مشفرًا. أدخل الأسرار في هذا النموذج المحلي فقط؛ لا ترسلها في المحادثة أو تضفها لملف متتبع.

عند النجاح، شغّل:

```powershell
npm run staging:verify
```

يعرض الفحص أسماء المفاتيح الناقصة ورسائل تحقق عامة فقط، ولا يطبع محتوى الأسرار. يرفض URL من مشروع آخر، أو دور قاعدة غير `edupro_staging_app`، أو تفعيل الترحيل/البذر التلقائي. تُحفظ نسخة محلية مشفرة بتقنية Windows DPAPI تحت `%LOCALAPPDATA%\EduPro\schoolfor-manus\staging\environment.dpapi`.

مخزن DPAPI محمي بحساب Windows الحالي على هذا الجهاز؛ لا يصلح وحده لاستعادة الأسرار على جهاز آخر أو حساب Windows آخر. قبل الانتقال إلى جهاز جديد، أعد تدوير مفاتيح Staging واحفظها في مدير أسرار معتمد. بيئة GitHub `staging` مقيّدة بفرع `codex/fees-module-repair`، لكنها ما زالت بلا أسرار، ولا تُستخدم كنسخة استعادة حتى تُضف إليها القيم اللازمة دون إدخالها إلى Git.

## إنشاء الربط المعزول في Cloudflare

إعداد `wrangler.staging.jsonc` يبقي `workers_dev=false` و`preview_urls=false` حتى يثبت تطبيق سياسة Cloudflare Access على حركة Worker كلها. بعد إنشاء Worker المستقل، فعّل Access من تبويب Worker واختر سياسة حساب Cloudflare للمالك، ثم وثّق التحقق في `docs/infrastructure/staging-resource-identity.json`. أداة النشر ترفض كشف hostname قبل هذا التحقق.

يلزم Hyperdrive جديد يستهدف مشروع Supabase أعلاه باستخدام دور البيانات المقيد. لا تربط `schoolfor-manus-staging` بأي من إعدادَي Hyperdrive الحاليين. لا تنشئ ربطًا إداريًا دائمًا للعامل؛ احتفظ بعنوان admin محليًا للاحتياج التشغيلي فقط، واستخدم `edupro_staging_app` في Worker.

بعد التحقق من Hyperdrive المقيد، أضف معرّفه إلى إعداد Staging فقط. خزّن مفتاح Supabase العام في متغير Worker عام، ومفتاح الخادم الخاص بمشروع Staging في مخزن Worker secrets. لا تنسخ مفاتيح الإنتاج. يبقى `FINANCIAL_WRITES_LOCKED=true` حتى اجتياز فحوص عزل المدارس ودورة الرسوم والسداد والقيد.

## تشغيل الاختبار المحلي واستعادته مستقبلًا

```powershell
npm run staging:verify
npm run dev:staging
```

يستمع الخادم المحلي على `127.0.0.1:4179`، ويفصل متغيرات البيئة الموروثة عن إعداد Staging، ويعطّل الترحيل والبذر التلقائي. تبقى الكتابة المالية مغلقة. لاختبار دورة مالية محلية معتمدة فقط، يُفعّل مسار UAT المحلي المحدد في القالب وتظل حواجز تأكيد UAT وفحص هوية المشروع مطلوبة.

عند تغيير الجهاز أو جلسة العمل، أعد إنشاء الملف بالقالب ثم استرجع القيم من مخزن الأسرار الدائم المعتمد، وشغّل `staging:verify` قبل الاتصال. إذا لم يعد بالإمكان استرجاع كلمة مرور، أنشئ/دوّر سرًا خاصًا بـStaging من لوحة Supabase ثم حدّث Cloudflare ووسيلة النسخ الآمنة؛ لا تستبدله بسر إنتاج.

## حالة المخطط والترحيلات

فحص 25 أكتوبر 2026 أعاد تكوين سلسلة الترحيلات محليًا في PostgreSQL 17.11، مع اختبار عزل مدرستين ورفض الكتابة العابرة للمدارس. توجد مقارنة مخطط مفصلة ونتائج هذا الاختبار في `staging-local-schema-validation-2026-10-25.md`.

قاعدة Staging الحية لديها 56 جدولًا وسجل ترحيلات فارغًا، بينما السلسلة النظيفة تعيد 114 جدولًا. لم يُسجّل baseline ولم تُطبق ترحيلات حية؛ يلزم أخذ نسخة قابلة للاستعادة، ومطابقة القيود والفهارس والسياسات والوظائف، ثم إعداد ترحيل إضافي آمن يعالج النواقص الفعلية دون إسقاط البيانات أو إعادة تشغيل التاريخ كاملًا.

## ما يلزم لإكمال التجهيز الحي

في هذه المرحلة لم يُثبت بعد حفظ اتصال قاعدة البيانات محليًا: يجب أن تظهر قيم DATABASE_URL وPLATFORM_ADMIN_DATABASE_URL وJWT_SECRET في التحقق، وأن يوجد ملف DPAPI المشفر. عامل Cloudflare المستقل وHyperdrive المنفصل لم ينشآ بعد. لا يُنشر اسم Worker للإنترنت قبل توثيق Access. لا يستخدم هذا الدليل Cloudflare production ولا اتصالها.
