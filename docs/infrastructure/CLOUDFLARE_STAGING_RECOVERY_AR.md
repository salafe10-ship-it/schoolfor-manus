# استعادة بيئة Staging عبر Cloudflare وSupabase

تاريخ التحقق: 24 أكتوبر 2026. هذا دليل تشغيل للبيئة المعزولة الخاصة بالاختبار؛ لا يستخدم إعدادات الإنتاج.

## نتيجة فحص الموارد

- مشروع Supabase المخصص للاختبار موجود مستقلًا: `edupro-school-erp-staging`، ومعرّف المشروع `vjcjscqgmijgzagshsca`.
- قائمة Hyperdrive في حساب Cloudflare احتوت إعدادين فقط: `schoolfor-manus-db` و`schoolfor-manus-admin-db`. إعداد `schoolfor-manus-db` متصل بمضيف Supabase مختلف عن مشروع Staging. لم يظهر إعداد Hyperdrive مستقل للاختبار.
- قائمة Workers لم تحتوِ عاملًا مستقلًا باسم `schoolfor-manus-staging`. يوجد ملف إعداد محلي `wrangler.staging.jsonc`، لكنه لا يضم Hyperdrive binding؛ وجود الملف لا يثبت وجود عامل منشور أو اتصال قاعدة.
- فحص بيئة GitHub السابقة لم يجد أسرار Staging. إعداد `production-database-migrations` خاص بالإنتاج، ولا يجوز إعادة استعمال أسراره في الاختبار.
- أُنشئت بيئة GitHub Actions باسم `staging`، وقُيّد استخدامها بفرع `master`. لا تحتوي حاليًا على أسرار أو متغيرات؛ سير العمل الدوري يقرأ عنوان الفحص من هذه البيئة عند إضافته بعد نشر عامل Staging.
- ملف `.env.staging` المحلي كان موجودًا، لكن مفاتيح الاتصال والمصادقة اللازمة فارغة. لم تُقرأ قيم أسرار الإنتاج ولم تُستخدم.

لم تُجرَ أي كتابة أو ترحيل على قاعدة Staging خلال هذا الفحص. Hyperdrive وWorkers الإنتاجية لم تُعدّل.

## تهيئة الملف المحلي بأمان

من جذر المستودع:

```powershell
npm run staging:prepare
```

ينشئ الأمر `.env.staging` من القالب إذا لم يكن الملف موجودًا، ويحافظ على أي ملف سابق دون استبداله. يقيّد صلاحيات Windows للمستخدم الحالي و`SYSTEM` و`Administrators`، أو يضبط صلاحية `0600` على الأنظمة الشبيهة بـUnix. الملف مستثنى من Git.

أدخل القيم الخاصة بمشروع Staging فقط باستخدام مدير أسرار معتمد أو أداة إدخال محلية آمنة. لا تضع أي قيمة في المحادثة أو ملف متتبع. بعد ذلك شغّل:

```powershell
npm run staging:verify
```

يعرض الفحص أسماء المفاتيح الناقصة ورسائل تحقق عامة فقط، ولا يطبع محتوى الأسرار. يرفض URL من مشروع آخر، أو دور قاعدة غير `edupro_staging_app`، أو تفعيل الترحيل/البذر التلقائي.

## إنشاء الربط المعزول في Cloudflare

قبل نشر عامل Staging، يلزم أن ينشئ مالك البيئة Hyperdrive جديدًا يستهدف مشروع Supabase أعلاه باستخدام دور بيانات محدود، ثم يتحقق بصريًا من اسم المشروع/المضيف واسم الدور في خصائص الاتصال. لا تربط `schoolfor-manus-staging` بأي من إعدادَي Hyperdrive الحاليين. كلمة مرور قاعدة البيانات تُدخل مباشرةً في Cloudflare/Supabase من قبل المالك ولا تحفظ في Git أو واجهة التطبيق.

بعد إنشاء ربط منفصل للداتا وربط إداري محدود عند الحاجة، تضاف معرّفات الربط إلى إعداد Staging فقط بعد التحقق من أن كلاهما يشير إلى المشروع المعزول. تحفظ مفاتيح Worker الخاصة بالاختبار في مخزن أسرار Staging منفصل، مع صلاحيات مقيدة؛ لا تنسخ مفاتيح الإنتاج. يبقى `FINANCIAL_WRITES_LOCKED=true` حتى اجتياز فحوص عزل المدارس ودورة الرسوم والسداد والقيد.

## تشغيل الاختبار المحلي واستعادته مستقبلًا

```powershell
npm run staging:verify
npm run dev:staging
```

يستمع الخادم المحلي على `127.0.0.1:4179`، ويفصل متغيرات البيئة الموروثة عن إعداد Staging، ويعطّل الترحيل والبذر التلقائي. تبقى الكتابة المالية مغلقة. لاختبار دورة مالية محلية معتمدة فقط، يُفعّل مسار UAT المحلي المحدد في القالب وتظل حواجز تأكيد UAT وفحص هوية المشروع مطلوبة.

عند تغيير الجهاز أو جلسة العمل، أعد إنشاء الملف بالقالب ثم استرجع القيم من مخزن الأسرار الدائم المعتمد، وشغّل `staging:verify` قبل الاتصال. إذا لم يعد بالإمكان استرجاع كلمة مرور، أنشئ/دوّر سرًا خاصًا بـStaging من لوحة Supabase ثم حدّث Cloudflare ووسيلة النسخ الآمنة؛ لا تستبدله بسر إنتاج.

## ما يلزم لإكمال التجهيز الحي

التهيئة المحلية أصبحت قابلة لإعادة الإنشاء، لكن مسار Staging الحي غير مكتمل بعد: لا يوجد Hyperdrive أو Worker مستقل منشور للاختبار، ولا مصدر أسرار Staging دائم جاهز يمكن استعادته. يلزم إدخال مالك الحساب سر قاعدة Staging في اتصال Hyperdrive جديد وحفظ مفاتيح الاختبار في مخزن Staging؛ بعد ذلك يمكن ربط العامل، تطبيق الترحيلات بعد مطابقة المخطط والنسخة الاحتياطية، واختبار الكتابة والعزل. لا يستخدم هذا الدليل Cloudflare production ولا اتصالها.
