# STU-AFFAIRS-P1-006-55 — تقرير التنفيذ

## الحالة

CODE-LEVEL CLOSED — DOCUMENT LIST SORTING TRUTHFULNESS

## النطاق

ضبط ترتيب قائمة مستندات الطلاب metadata في الواجهة فقط، مع احترام ترتيب العقد الكانوني وعدم الادعاء بترتيب شامل خارج النتائج المحملة.

## التغييرات

- الحفاظ على `الترتيب الكانوني الحالي` كما يصل من endpoint، دون إضافة `sortBy` أو `sortOrder` إلى API.
- إضافة ترتيب اختياري client-side على النتائج المحملة فقط: العنوان تصاعديًا، المرجع تصاعديًا، والإصدار تنازليًا.
- استخدام مقارنة deterministic مع `id` ككاسر تعادل، دون تعديل مصفوفة `rows` الأصلية.
- إظهار عبارة صريحة بأن الترتيب الاختياري يطبق على النتائج المعروضة حاليًا فقط.
- عند البحث أو الفلترة أو canonical refresh، يعاد اشتقاق الترتيب من `rows` الجديدة، ولا تستخدم قائمة سابقة.
- بقاء selection/details مرتبطين بـ`documentId`، فلا يؤدي تغيير الترتيب إلى فتح سجل خاطئ.
- الحفاظ على Error ≠ Empty، no-match semantics، sequence guards، read-only retry، dirty state، submission guard، accessibility، وno false-success.

## حدود العقد الحالي

العقد الحالي يعيد الحقول اللازمة للترتيب المحلي (`title`, `document_reference`, `current_version_number`, `id`) ويرتب افتراضيًا في المستودع حسب `updated_at DESC, id`. لم تتم إضافة عقد ترتيب خادمي جديد، والترتيبات الاختيارية معلنة صراحة بأنها محلية على الصفحة الحالية.

## النطاق المستبعد

لا تغييرات في API أو backend أو الخدمات أو المستودعات أو قاعدة البيانات أو SQL أو RLS أو Storage أو المصادقة أو العزل.
