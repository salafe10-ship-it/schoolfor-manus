# سجل فجوات وحدة المخزون مقارنة بممارسات ERP/WMS المؤسسية

**تاريخ المراجعة:** 2026-09-30
**النطاق:** وحدة المخزون والمشتريات في هذا المستودع، مع مراجعة واجهة المدرسة المنشورة.
**الغرض:** تحديد ما هو متحقق حاليًا وما لا يجوز وصفه بأنه مكافئ لـ WMS مؤسسي متقدم. هذه مقارنة نطاق وقدرات، وليست شهادة امتثال أو ادعاء تكافؤ كامل مع SAP أو Oracle أو Dynamics 365.

## الخلاصة التنفيذية

الوحدة توفر أساس ERP مدرسيًا عمليًا: دليل الأصناف، التصنيفات والوحدات، الموردون والمستودعات، أرصدة موزعة على المستودعات، الاستلام والمشتريات، التحويل والصرف، محاضر الجرد المعتمدة، تقارير التقييم وإعادة الطلب، وسجل/ترحيل محاسبي عبر المسار الكانوني. طريقة التكلفة الظاهرة والمنفذة هي المتوسط المرجح؛ FIFO غير مفعّل.

لكنها **ليست WMS متقدمًا**: لم يثبت وجود مواقع تخزين داخلية بمستوى الممر/الرف/الرفّ الصغير/الخانة، أو تتبع الدفعات/الأرقام التسلسلية والصلاحية، أو تشغيل مستودع محمول بالباركود، أو موجات الالتقاط والإيداع الموجّه، أو جلسات جرد دوري مع الوسوم وقفل الرصيد. لذلك الوصف الدقيق هو «مخزون ERP مدرسي متعدد المستودعات» لا «تكافؤ كامل مع WMS عالمي».

## القدرات المثبتة في النطاق الحالي

- صفحات تشغيل منفصلة: لوحة، أصناف، فئات/وحدات، موردون، مستودعات، حركات، جرد وتسويات، مشتريات، تقارير، تدقيق، وإعدادات.
- رصيد الصنف موزع حسب المستودع، مع حركات استلام وصرف وتحويل ومحاضر جرد خاضعة للاعتماد.
- مسار المشتريات والاستلام مرتبط بالمخزون، مع الربط المحاسبي عبر التكامل الكانوني بدل إنشاء قيد مباشر من شاشة المخزون.
- الاستيراد CSV يستند إلى معرفات الأدلة ولا ينشئ أرصدة افتتاحية وهمية.
- الجرد الحالي يتطلب إدخال كمية فعلية صراحة واعتماد محضر التسوية؛ الشاشة تعرض بوضوح أن المتوسط المرجح هو المنفذ وأن FIFO غير متاح.
- في الفحص الحي للمدرسة المحددة كانت بيانات المخزون المعروضة صفرية ولا توجد تهيئة/حركات ظاهرة؛ لم تُنشأ بيانات تجريبية في سجل المدرسة لإثبات تدفق كتابة حي.

## سجل الفجوات والأولوية

| الأولوية | الفجوة غير المتحققة | أثرها | الحد الأدنى لإغلاقها مستقبلًا |
|---|---|---|---|
| P1 | مواقع داخل المستودع: ممر/رف/مستوى/خانة، أنواع المواقع، سعة/أبعاد، الحظر، ومصدر/وجهة الإدخال والالتقاط | لا يمكن تحديد موضع الصنف بدقة أو توجيه عامل المستودع إلى خانة فعلية؛ حقل المستودع وحده لا يساوي bin-level WMS | نموذج مواقع هرمي مرتبط بالمستودع، التحقق من السعة والحظر، دعم مواقع الاستلام/الفحص/الالتقاط، وتقارير الأرصدة على مستوى الموقع |
| P1 | تتبع رقم الدفعة/التسلسل/دفعة المورد وتاريخ الإنتاج/الصلاحية والتتبع العكسي/الأمامي | لا يمكن عزل دفعة أو استدعائها، إثبات مصدرها أو معرفة الصرف الذي استهلكها؛ مهم للأدوية والمواد الحساسة | أبعاد تتبع إلزامية حسب الصنف، حفظها في كل سطر مستند/حركة، تقارير trace forward/backward، وتنبيه صلاحية وسياسة FEFO عند الحاجة |
| P1 | تنفيذ مستودع محمول: مسح باركود/QR للموقع والصنف والدفعة/اللوحة وتأكيد الالتقاط/الإيداع | الإدخال اليدوي يزيد أخطاء الصنف والموقع ولا يوفر توجيهًا لحظيًا للمشغل | واجهة جوال/ماسح مرتبطة بمهام خادمية وصلاحيات وسجل تدقيق، مع رفض عدم تطابق الصنف/الموقع/الدفعة |
| P2 | جرد دوري متقدم: جلسات/وسوم منفصلة، عدّ أعمى، إعادة عدّ، نطاق حسب الموقع/الأبعاد، وسياسة تمنع تغيير الرصيد أثناء العد | الجرد الحالي محضر للصنف والمستودع مع اعتماد، لكنه ليس tag/cycle-count engine ولا يثبت حجز الرصيد خلال جلسة طويلة | جلسات عد ذات معرفات ووسوم، فصل القيمة الدفترية عن شاشة العادّ، فرق واعتماد/إعادة عد، وخيار قفل أو تسوية الحركات المتزامنة |
| P2 | الإيداع الموجّه، الالتقاط حسب المسار/الأولوية، موجات العمل، منطقة التجهيز، وتأكيد الشحن/التسليم | التحويل والصرف مستندان مخزنيان، لكنهما لا يقدمان محرك تنفيذ مهام WMS أو تحسين مسارات العامل | نموذج مهام عمل ومستودع موجّه بالموقع، قواعد putaway/picking قابلة للتهيئة، وتأكيد الكمية والموقع بالماسح |
| P2 | إعادة تزويد مواقع الالتقاط والتخطيط حسب الطلب/المهلة/المخزون المحجوز | نقطة إعادة الطلب والتقرير الحاليان لا يعادلان تخطيط احتياج متعدد المواقع أو مهام replenishment | إعدادات حد أدنى/أقصى ومهلة وتغطية حسب المستودع/الموقع، وحساب احتياج قابل للمراجعة قبل إنشاء أمر شراء أو مهمة تحويل |
| P2 | طرائق تكلفة بديلة مثل FIFO | التقارير/الجرد يعتمدان المتوسط المرجح فقط؛ لا يصلح ذلك تلقائيًا لسياسة محاسبية تشترط FIFO | اعتماد الطريقة على مستوى السياسة، ترحيل واختبارات تقييم معتمدة قبل إضافة أي خيار؛ لا إظهار خيار غير منفذ |

## مقارنة مرجعية محددة

- توثق Microsoft Dynamics 365 مواقع الإيداع والالتقاط ضمن مستودع بمسميات/إحداثيات الممر والرف والرفّ الصغير والخانة، مع خصائص الموقع وأنواعه وحظره؛ النطاق الحالي لدينا يتوقف عند المستودع، لذا توجد فجوة حقيقية في دقة الموقع والسعة والحظر. [Inventory locations](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/inventory-locations)
- يتيح Dynamics 365 تتبعًا تاريخيًا حسب أبعاد تتبع مثل الدفعة والرقم التسلسلي ودفعة المورد، وباتجاه أمامي أو عكسي مع أبعاد التخزين والفترة؛ هذه القدرات غير مثبتة في الوحدة الحالية. [Item and raw material tracing](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/trace-items-raw-materials-inventory-production-sales)
- يصف Dynamics 365 عدّ الوسوم وتحويله إلى سجل جرد، مع العد وفق أبعاد مثل المستودع وخيار منع تحديث الرصيد خلال الجرد؛ الوحدة الحالية لديها محاضر واعتماد، لكنها لا تطبق دورة الوسوم/القفل هذه. [Inventory tag counting](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/inventory-tag-counting)
- يتضمن تنفيذ WMS المحمول تأكيد الدفعة أو الرقم التسلسلي أو لوحة الترخيص والموقع أثناء الالتقاط والعمل؛ لا تعرض الوحدة الحالية تدفق تأكيد محمول/مسح لهذه الأبعاد. [Batch, serial, license plate, and location confirmation](https://learn.microsoft.com/en-us/dynamics365/supply-chain/warehousing/batch-and-license-plate-confirmation)

## الحكم والتوصية

يمكن وصف الوحدة بأنها أساس تشغيل مخزون مدرسي متعدد المستودعات مع دورة مستندية ومحاسبية مترابطة. لا يصح إغلاق فجوة WMS أو الإعلان عن تكافؤ شامل مع الأنظمة العالمية قبل تنفيذ البنود P1 واختبارها ببيانات قبول معزولة؛ ويظل P2 توسعًا مرحليًا بحسب حاجة المدارس وحجم التشغيل. إعداد المدرسة الفعلي (المستودعات والأصناف والموردون والأرصدة الافتتاحية المعتمدة) مسؤولية تشغيلية منفصلة، ولم يُنفذ ضمن هذا الفحص حفاظًا على بيانات المدرسة الحية.

## حدود الفحص

- فحص مصدر وواجهة قراءة فقط؛ لم تُنشأ أو تعدّل مستندات/أرصدة في المدرسة الحية.
- اختبارات المخزون الآلية لا تثبت بمفردها تنفيذ مسح مادي أو تكامل أجهزة باركود أو صلاحية تدفق إنتاجي حقيقي.
- المرجع المقارن هنا وثائق Microsoft الرسمية؛ وهو معيار ملموس للقدرات، لا مسحًا كاملاً لكل إصدار أو ترخيص من SAP/Oracle/غيرهما.
