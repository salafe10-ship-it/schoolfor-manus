## البنود التي تحتاج دليلًا خارجيًا قبل ختم التسليم

1. نشر النسخة الحالية على Render ثم حفظ نتيجة حية لـ `/api/health` و`/api/ready` وتسجيل الدخول — **تم إثبات النشر والجاهزية؛ اختبار تسجيل الدخول ما زال يحتاج حساب UAT معتمدًا**.
2. اعتماد SMTP وإثبات وصول رسالة استعادة كلمة المرور ورابطها.
3. تنفيذ نسخة إنتاج مشفرة واختبار Restore موثق مع سياسة احتفاظ.
4. ربط النطاق التجاري وإثبات DNS وSSL عبر فحص خارجي موثوق.
5. اعتماد خطة Render أو قبول قيد الخطة المجانية كتابةً.
6. تنفيذ اختبار عزل حي بحسابي مدرستين مستقلين وحفظ دليل منقح من الأسرار.
7. قناة المراقبة الحالية مضافة في `.github/workflows/staging-uptime.yml`؛ تفحص الجاهزية كل خمس دقائق وتفتح/تغلق Issue عند الفشل والتعافي. اعتماد قناة مناوبة/تجميع سجلات خارج GitHub Actions يبقى قرارًا تشغيليًا منفصلًا.

لا يتم تغيير الحالة إلى `UNIT CLOSED` أو `COMMERCIAL HANDOVER APPROVED` اعتمادًا على تغييرات المصدر وحدها. بعد إرفاق الأدلة السبعة أعلاه، يعاد تشغيل فحص التسليم وتُحدّث الحالة في محضر مستقل؛ أما سجل الوحدات العام فيبقى `IN PROGRESS` لأن وحدات أخرى ما زالت تحمل بوابات إغلاق منفصلة.
