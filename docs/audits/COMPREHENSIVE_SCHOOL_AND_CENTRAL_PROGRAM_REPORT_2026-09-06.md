## 1. الملخص التنفيذي

البرنامج عبارة عن منصة SaaS متعددة المدارس تربط الإدارة المركزية ببوابات المدارس والمستأجرين ضمن قاعدة بيانات PostgreSQL/Supabase واحدة مع عزل سياقي وصلاحيات دقيقة. المنصة تجمع الإدارة الأكاديمية والطلابية والمالية والتشغيلية والرقابية في نظام واحد، وتمنح الإدارة المركزية قدرة إنشاء المدارس وإدارتها ومراقبة جاهزيتها وإصدار التحديثات لها.

نتيجة المراجعة الحالية:

- **البنية البرمجية:** مكتملة وقابلة للبناء.
- **بوابة المدرسة:** معزولة عن الإدارة المركزية عند استخدام رابط المدرسة.
- **الإدارة المركزية:** متاحة للمدير الفائق فقط وتحتوي على إدارة المدارس والمستأجرين وRBAC والأمن والنسخ والبنية التحتية.
- **قاعدة البيانات:** صحيحة ومتصلة ومحدثة دون حذف البيانات السابقة.
- **النشر:** ناجح وحالة Render هي `Deploy succeeded | Live`.
- **التسليم التجاري:** يحتاج اعتماد اختبارات التشغيل الفعلية والنسخ الاحتياطي والاستعادة قبل إعلان الإغلاق النهائي.

## 2. صورة المنظومة

```text
الإدارة المركزية (Platform / SuperAdmin)
        │
        ├── إنشاء المستأجر والمدرسة والفروع
        ├── إدارة الخطط والصلاحيات والأمن والنسخ
        ├── مراقبة الحوادث والإشارات وحالة المنصة
        └── إصدار قوالب وتحديثات مستهدفة للمدارس
        │
        ▼
بوابة المدرسة (School Workspace)
        │
        ├── الطلاب وأولياء الأمور والحضور
        ├── الامتحانات والنتائج والمكتبة
        ├── المعلمون والموظفون والحسابات
        ├── المخزون والعهد والنقل والزي المدرسي
        └── التقارير وسجلات الرقابة والإعدادات
        │
        ▼
PostgreSQL / Supabase + API Server + RLS + Audit Trail
```

## 3. الإدارة المركزية

الإدارة المركزية هي طبقة التحكم في المنصة وليست مساحة تشغيل يومية للمدرسة. تظهر أدواتها للمدير الفائق فقط، وتشمل:

| المجال | الوظائف |
| --- | --- |
| الرقابة المركزية | إحصاءات المنصة وتدفق الموارد وحالة المستأجرين |
| المدارس والمستأجرون | إنشاء المدارس، إدارة الحالات والفروع، ربط المالك، ومتابعة دورة المدرسة |
| RBAC والحوكمة | كتالوج الصلاحيات، الأدوار، المنح، المراجعة، وسياسات الوصول |
| الأمن والتهديدات | مؤشرات أمنية، أحداث حساسة، ومتابعة الرفض أو الخلل |
| النسخ والتعافي | مستودع النسخ ومراقبة جاهزية التعافي من الكوارث |
| الخطط والمالية | الباقات، الاستحقاق، وعلاقة الحسابات بالخدمة |
| البنية السحابية | حالة الاتصالات، مؤشرات الخدمة، وقنوات التشغيل |
| مركز الحوادث | فتح الحوادث، تعيين المالك، الإشارات، الأولوية، الحالة، سبب الجذر، وخطة المعالجة |

## 4. بوابة المدرسة

كل مدرسة تعمل ضمن سياقها الخاص، ويظهر لها فقط ما يتوافق مع دور المستخدم وصلاحياته. أقسام المدرسة الموجودة في واجهة التشغيل:

### الخدمات الطلابية والتعليمية

- لوحة التحكم العامة.
- الطلاب وشؤون القيد والملفات والوثائق وأولياء الأمور.
- الحضور والانصراف.
- الامتحانات والنتائج.
- المكتبة المدرسية.

### الموظفون والمالية

- المعلمون والموظفون.
- الحسابات العامة والدفع.
- القيود والتقارير المالية ومسارات الاعتماد حسب الصلاحية.

### التشغيل والمرافق

- المخزون والعهد.
- النقل والترحيل المدرسي.
- الزي المدرسي.
- الأصول الثابتة والمشتريات عند تفعيل الوحدة.

### الرقابة والإعدادات

- سجلات الرقابة والعمليات.
- المراجعة العامة.
- الإعدادات العامة.
- مخطط Supabase SQL، وهو مقيّد عن مستخدم المدرسة العادي.

## 5. الأدوار والصلاحيات

الأدوار المعرفة في النظام هي:

| الدور | الاستخدام |
| --- | --- |
| SuperAdmin | الإدارة المركزية والتحكم في المنصة |
| SchoolAdmin | إدارة المدرسة الرئيسية |
| Teacher | هيئة التدريس |
| Accountant | الحسابات والرواتب |
| Parent | متابعة الطالب وملفه |
| Control | لجنة الامتحانات والنتائج |
| Auditor | المراجعة والرقابة |
| Student | الوصول المسموح للطالب |

الصلاحيات ليست مجرد إخفاء أزرار؛ يتم فحصها في الواجهة وفي الخادم. مثال ذلك صلاحيات `Student.View` و`Student.Write` و`Student.Delete` و`Student.Export`، مع فشل آمن عند غياب التلميح الموثوق للصلاحيات.

## 6. دورة إنشاء مدرسة وتشغيلها

1. يطلب العميل إنشاء مدرسة أو مساحة تشغيل.
2. تنشئ الإدارة المركزية المستأجر والمدرسة والفرع وتحدد الكود والنطاق.
3. يربط النظام مالك المدرسة أو حساب المدير ويصدر سياق المدرسة.
4. تُطبَّق الخطة والقوالب والصلاحيات الافتراضية.
5. يفتح العميل رابط المدرسة؛ تظهر بوابة المدرسة مباشرة دون زر الإدارة المركزية.
6. يتم تسجيل الدخول ضمن `schoolContext` والتحقق من أن المستخدم مخول لنفس المدرسة.
7. يبدأ العميل دورة التشغيل: الطلاب، الموظفون، الحضور، الامتحانات، المالية، المخزون، والنقل.
8. تحفظ العمليات في قاعدة البيانات مع سجل رقابي، وتظهر مؤشرات الأخطاء والحوادث للإدارة المركزية.
9. عند إصدار تحديث أو قالب، تطبقه الإدارة المركزية على المدرسة المستهدفة مع إمكانية المتابعة والرجوع حسب سياسة الإصدار.

## 7. الأمن والعزل

- الخادم Express يتعامل مع المصادقة الموثوقة وجلسات JWT.
- سياق المدرسة يمر من الواجهة إلى الخادم ولا يعتمد على اختيار بصري فقط.
- تسجيل دخول مدرسة لا يعيد المستخدم إلى الإدارة المركزية تلقائياً.
- المستخدم المركزي لا يُفترض أن يعمل تلقائياً كمدير داخل كل مدرسة؛ يلزم وجود هوية مدرسية مصرح بها.
- قاعدة البيانات تستخدم RLS وسياسات عزل المستأجرين/المدرسة.
- سجلات الرقابة تسجل العمليات الحساسة وتمنع اعتبار التخزين المحلي مصدراً نهائياً عند فشل الحفظ المركزي.
- الأسرار لا تدخل المستودع ولا التقرير.

## 12. البنود التي تحتاج متابعة

1. إنشاء هوية مدرسة نشطة لمدرسة ثانية ثم تنفيذ اختبار تشغيل فعلي بحساب مدرسة مستقل وحساب مركزي مستقل.
2. إعادة اختبار عزل مدرستين في نفس الوقت ومنع أي تسرب في البيانات أو الجلسات.
3. تفعيل وتوثيق النسخ الاحتياطي والاستعادة من لوحة Supabase وتجربة استعادة منفصلة.
4. اعتماد مزود SMTP واختبار استعادة كلمة المرور برسالة فعلية.
5. تزويد النطاق التجاري وضبط DNS والتحقق من SSL.
6. التحقق من أن Blueprint يقرأ فرع Render المثبت عند إعادة الإنشاء.
7. تم تنظيف الملفات المحلية غير المتتبعة بنقلها إلى أرشيف مؤقت قابل للاسترجاع.
8. أُجريت خطة اختبار حمل غير مغيرة؛ يلزم تصريح منفصل لتشغيل الحمل الصناعي الفعلي.

## 13. قرار المراجعة

البرنامج **جاهز للتشغيل المرحلي على Render ومربوط بقاعدة البيانات الصحيحة**. الإدارة المركزية وبوابات المدارس تعملان ضمن فصل واضح، والبنية البرمجية والاختبارات والنشر الحي موثقة.

لا يُنصح بإعلان التسليم التجاري النهائي قبل إغلاق بنود الاختبار التشغيلي الحقيقي، النسخ الاحتياطي والاستعادة، واستعادة كلمة المرور والنطاق التجاري.
