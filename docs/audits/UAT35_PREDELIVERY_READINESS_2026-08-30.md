# تقرير جاهزية UAT لخمسة وثلاثين مدرسة

التاريخ: 30 أغسطس 2026  
البيئة المفحوصة: SchoolForManus UAT / Staging  
الحالة: **غير مجازة بعد لإنشاء بيانات UAT أو الإغلاق الإنتاجي**

## ما تم تنفيذه والتحقق منه

- تنفيذ فحص قراءة فقط لبنية قاعدة البيانات باستخدام `scripts/uat35-preflight.ts`، من دون عرض بيانات أعمال أو أسرار اتصال.
- تطبيق ترقية `202608271500_hr_canonical_records.sql` والتحقق من إنشاء `hr_database` مع تفعيل RLS. هذا هو المصدر المعتمد للوظائف والموظفين، وليس تخزين المتصفح.
- التحقق من وجود هوية UAT نشطة في المستأجر المرجعي، بحيث يمكن لاحقاً تسجيل التغييرات بصورة قابلة للتدقيق.
- تدقيق مصدر شاشات الإدارة المركزية وأزرارها، بالإضافة إلى فحوصات TypeScript وبناء SPA واختبارات الوحدات المستهدفة المنفذة سابقاً.
- اجتازت خمسة ملفات اختبار مستهدفة، بإجمالي 36 اختباراً: حواجز العزل بين المستأجرين والمدارس والفروع، سياسات RLS للطلاب، عزل علاقات أولياء الأمور، عقد وحدات الزي/النقل، وعقد فحص UAT.

## نتيجة بنية البيانات

| نطاق التشغيل | الحالة | الملاحظة |
|---|---|---|
| المستأجرون، المدارس، الفروع، المستخدمون، الطلاب | موجود مع RLS | قابل للبناء عليه بعد مسار تهيئة مركزي موثوق |
| الموارد البشرية (وظائف وموظفون) | موجود الآن مع RLS | الترقية طُبقت وتحققت |
| المخزون والمشتروات | موجود | `inventory_database` مع RLS |
| الحسابات | موجود | `financial_portal_snapshots` مع RLS |
| النقل والترحيل | غير موجود | لا توجد جداول `buses` أو `student_transportation` في UAT |
| الزي المدرسي | غير مكتمل | لا توجد `student_uniform_accounts`، كما أن الشاشة تعتمد حالة React محلية |
| الأدوار والصلاحيات | غير مجاز للعزل | جدولَا `roles` و`permissions` بلا RLS في UAT |
| سجل التدقيق | غير متحقق باسم `audit_logs` | المصدر المعتمد في المنصة هو `audit_events`؛ يلزم ربط دورة UAT به |

## تدقيق الإدارة المركزية

الواجهة موحدة جزئياً من الناحية البصرية، لكن لم تستوف بعد شرط التشغيل المركزي الحقيقي. النتائج الأهم:

| الشاشة | النتيجة الحالية | قرار الاعتماد |
|---|---|---|
| إدارة المدارس | نموذج الإضافة يفشل بأمان عند غياب الخدمة، لكن التعديل/التجميد/الأرشفة/الحذف/النسخ تغيّر حالة React محلياً | غير معتمد |
| إدارة المستخدمين | الإضافة تفشل بأمان عند غياب خدمة الهوية، لكن تعديل الحسابات وقفلها وإعادة كلمات المرور ما زال محلياً | غير معتمد |
| إدارة الوحدات | تعتمد `localStorage` | غير معتمد |
| لوحة العمليات | تشمل تغييرات محلية ومحاكاة لبعض النسخ والدعم | غير معتمد |
| الفروع | إنشاء وتعديل وترحيل بعدّادات محلية ومحاكاة | غير معتمد |
| النسخ الاحتياطية وصحة النظام | أزرار تتضمن مؤقتات نجاح محاكى | غير معتمد |
| التنبيهات والموارد | يفشلان بأمان عند غياب الخدمة المركزية | سلوك آمن، لكن غير تشغيلي |
| RBAC | واجهة مستقلة عن RLS الفعلي في قاعدة UAT | غير معتمد |

## لماذا لم تُنشأ المدارس الـ35 الآن

إنشاؤها الآن سيخالف شرطين أساسيين طلبتهما المهمة: أن تكون البيانات قابلة للحذف بأمان، وأن يكون العزل كاملاً. لا توجد حالياً طبقة نقل/زي موثوقة لتستوعب البيانات، كما أن RLS للأدوار والصلاحيات غير مفروض. إنشاء السجلات عبر حالة الواجهة أو التخزين المحلي سيعطي نتيجة مضللة ولا يصلح للتسليم.

## مسار الإغلاق المطلوب

1. إنشاء واجهة خدمة مركزية محكومة بـ `Platform.Admin` لإضافة المدارس من شاشة الإدارة المركزية، مع معرف تشغيل UAT ثابت وبادئة `UAT35-`.
2. إكمال ترحيل وحفظ النقل والزي في جداول/واجهات API معزولة، ثم إزالة أي مسار تشغيل يعتمد حالة React أو التخزين المحلي.
3. تفعيل RLS وسياسات القراءة/الكتابة على `roles` و`permissions` وارتباطاتها، ثم اختبار الرفض المتبادل بين مدرستين.
4. ربط كل زر إداري بواجهة خادم موثقة أو إظهاره كغير متاح؛ يمنع إظهار نجاح لمحاكاة محلية.
5. عند اجتياز الفحص، ينشئ مولد مركزي 35 مدرسة تحت تشغيل UAT واحد، ويضيف لكل مدرسة وظائف وموظفين وطلاب ومخزوناً ومشتريات ولقطة حسابات. الحذف سيكون محصوراً بمعرف التشغيل نفسه داخل معاملة قابلة للتدقيق.
6. تنفيذ اختبارات إيجابية وسلبية: قراءة وكتابة وتعديل وحذف عبر مدرستين مختلفتين، ثم اختبار الواجهة والأزرار بواسطة حساب مدير منصة فعلي.

## حكم التسليم الحالي

لا يصح اعتماد «العزل التام» أو «اختبار كل شاشة وزر» في هذه المرحلة. الاعتماد المهني يتطلب إنجاز البنود الستة أعلاه ثم إرفاق نتيجة تشغيل UAT الرقمية (عدد المدارس والسجلات ونتائج اختبارات الرفض) قبل الإغلاق الإنتاجي.
