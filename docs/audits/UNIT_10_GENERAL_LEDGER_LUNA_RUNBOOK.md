# UNIT 10 — General Ledger LUNA Runbook

## الحالة الحالية

- قرار SOL: **NOT READY للإغلاق المالي**.
- وضع المصدر الحالي: `snapshot_read_only`.
- القراءة مسموحة من المصدر المركزي، لكن لا يوجد بعد كاتب كانوني معتمد لمسار سند ← قيد ← أستاذ عام.
- لم تُنشأ قيود أو سندات أو أرصدة جديدة أثناء هذه المعالجة.

## تشغيل مراجعة UAT-B

1. افتح بيئة UAT-B وسجّل الدخول بالحساب المصرح به من مسؤول البيئة.
2. افتح **الحسابات** وتحقق من شريط الحالة: المصدر متصل **للقراءة فقط**.
3. راجع **لوحة المؤشرات**؛ يجب أن يظهر `غير متحقق — قراءة فقط`، ولا يظهر “متوازن” أو “متاح للصرف”.
4. راجع **التقارير المالية**؛ يجب أن يظهر تنبيه أن الأرقام نسخة عرض غير معتمدة، وأن فرق الميزانية ظاهر كما هو من المصدر.
5. راجع **سندات القبض/الصرف**؛ زر الترحيل يجب أن يكون معطلاً.
6. راجع **إقفال السنة**؛ يجب أن يظهر أن الإقفال متوقف ولا يوجد حفظ محلي بديل.

## الممنوع حالياً

- إنشاء أو ترحيل سند قبض أو سند صرف.
- إضافة مورد أو استيراد أصول أو تنفيذ حوالة أو تعديل دليل الحسابات.
- اعتماد تسويات أو إقفال سنة أو فتح سنة جديدة.
- اعتبار CSV/الطباعة قائمة مالية رسمية؛ المتاح نسخة عرض فقط.
- إصلاح قيد مفقود بمعرف مدرسة أو حساب أو مركز تكلفة افتراضي.

## شروط فتح التنفيذ لاحقاً

لا يُغيّر وضع الكتابة إلى `ledger_ready` إلا بعد اعتماد مالك المنتج/المالية لعقد يشمل:

- معرف المدرسة والفرع والفترة في كل حركة، مع عزل tenant موثق.
- خدمة كانونية ذرية لمسار Receipt/Payment → Journal → GL مع رقم إصدار وتعارضات version.
- حالات Save/Post/Approve/Unpost/Cancel وسجل تدقيق قابل لإعادة الإنتاج.
- مصدر رسمي للذمم، الأصول، الموردين، مراكز التكلفة، التقارير والإقفال.
- اختبارات UAT مصرح بها لبيانات صغيرة، مع رفض cross-tenant وclosed-period.

## فحوص التسليم

```text
npm run lint
npx vitest run --passWithNoTests
npm run build
```

النتيجة المثبتة في هذه الجولة: lint ناجح، `279` ملف اختبار ناجح، `668` اختباراً ناجحاً، وبناء الإنتاج ناجح. تحذيرات حجم الحزم و`import.meta` في CJS قائمة قديمة ولا تمنع البناء.

## إغلاق جولة LUNA الثانية — 2026-08-23

- تم فحص كل شاشة في قائمة الحسابات العامة في UAT-B دون تنفيذ معاملة مالية.
- تم تعطيل الاستيراد العام عندما يكون المصدر `snapshot_read_only`.
- تم تعطيل إنشاء/حذف/حفظ/ترحيل/اعتماد القيود، بما فيها أزرار قائمة القيود وشاشة القيد المفتوح.
- تم تعطيل الحوالات وحقولها التنفيذية، وإنشاء الأصول وإلغاؤها، وإلغاء سندات القبض والصرف في وضع القراءة فقط.
- تم تخفيف رسائل التقارير والإقفال التي كانت توحي باعتماد أو توازن رسمي.
- شاشة إدارة الصلاحيات أعادت `403_FORBIDDEN` للحساب الحالي، ولم تُعتبر هذه النتيجة فشلاً في الحسابات العامة.
- فحوص المتصفح النهائية: لا أخطاء JavaScript، المصدر ظاهر كقراءة فقط، والأفعال الحساسة disabled أو معنونة بوضوح.

نقطة التشغيل المستقلة لهذه الجولة هي commit الإصلاح التالي بعد حفظ التغييرات المحاسبية فقط:

`fix(accounting): close legacy write paths in UAT read-only mode`

## نقطة التراجع

التراجع يكون عبر مراجعة commit الإصلاح الموثق في Git بعد اعتماده، مع إبقاء قرار SOL وبيانات المصدر المركزي دون أي حذف أو reset قسري.

## تشغيل جولة LUNA الثالثة — 2026-08-24

1. تطبيق خطة SOL على بقايا العبارات غير الموثقة في شجرة الحسابات والتقارير والإقفال.
2. تشغيل `npm run lint` مباشرة بعد كل تعديل تركيبـي.
3. تشغيل اختبار عقد ACC-001 ثم مجموعة الاختبارات الكاملة.
4. تشغيل `npm run build` للتحقق من حزمة الإنتاج.
5. إعادة فحص المتصفح للشاشات الحساسة والأزرار المعطلة، دون إنشاء/ترحيل/إقفال مالي.
6. تنفيذ مراجعة SOL ختامية وحفظ checkpoint محاسبي مستقل.

في هذه الجولة أضيفت حواجز صريحة لنتائج تدقيق شجرة الحسابات، ووسوم نسخة العرض في التقارير التفصيلية، وحالات الإقفال السبعة. أي نتيجة تعتمد على snapshot تبقى `غير متحقق — قراءة فقط`.
