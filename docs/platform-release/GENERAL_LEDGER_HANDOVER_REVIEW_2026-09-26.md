# تقرير مراجعة تسليم وحدة الحسابات العامة

تاريخ المراجعة: 2026-09-26

## النطاق

تمت مراجعة البنية الرئيسية للوحدة، `GeneralLedgerPortal`، وتبويبات دفتر الأستاذ، شجرة الحسابات، القيود اليومية، سندات القبض والصرف، العملاء والموردين، الأصول الثابتة، الموازنة، الإقفال، التقارير، أدوات الحساب، وخرائط الحسابات، إضافة إلى طبقة الترحيل الكانونية ومسارات الحفظ والتصدير.

## الحكم التنفيذي

الوحدة غنية وظيفيًا وقابلة للتشغيل في نطاق المدرسة، لكنها لا تستحق إعلان «جاهزة للتسليم المالي المؤسسي الكامل» بعد. أقوى ما فيها هو وجود مصدر مالي كانوني، ترحيل مزدوج، مفتاح عدم التكرار، ربط المستند بالقيد، عكس القيود، فحص الفترة المالية، وسجل تدقيق. أضعف ما فيها أن بعض الوظائف ما زالت قراءة فقط أو محاكاة، وأن اختبارات دورة العمل الكاملة والتزامن والإقفال البنكي غير مثبتة بتغطية تسليم آلية.

## 1. الوظائف التي يغطيها النظام

| المجال | النتيجة |
|---|---|
| لوحة الأستاذ وميزان المراجعة | موجودة، مع مؤشرات وحسابات حسب الحساب ومركز التكلفة |
| شجرة الحسابات | موجودة، مع إضافة/تعديل/تعطيل واستيراد وفحص خرائط |
| القيود اليومية | موجودة، مع مسودة/اعتماد/ترحيل وعكس وتفصيل ومرفقات |
| سندات القبض والصرف | موجودة، مع ربط بالقيد والطباعة والمرفقات والعكس |
| تقارير الدخل والميزانية والتدفقات وكشف الحساب | موجودة مع drill-down، لكنها تعتمد على جاهزية المصدر الكانوني |
| الأصول والإهلاك | موجودة مع الاستيراد والتعديل والنقل والبيع والاستبعاد وجدول الإهلاك |
| الموازنة | موجودة كتحليل ومتابعة؛ الربط الكامل بالالتزام وأمر الشراء غير مكتمل |
| الإقفال | شاشة وفحوصات وإجراءات موجودة؛ يلزم إثبات UAT وإعادة فتح بصلاحية مستقلة |
| الموردون والعملاء | موجودة جزئيًا؛ لا تظهر دورة مشتريات/ذمم كاملة بمطابقة ثلاثية |
| العملات | أداة تحويل ومؤشرات عملة موجودة؛ دفتر موازٍ وإعادة تقييم فروق الصرف غير مثبتين |
| البنك | تحويلات ومؤشرات موجودة؛ استيراد كشف ومطابقة بنكية حقيقية غير مكتملة |
| التصدير والطباعة | طباعة موجودة وتصدير تقارير؛ تم إصلاح تصدير Excel ليخرج XLSX حقيقيًا |

## 2. النواقص الوظيفية حسب المنطق المحاسبي

### مانعة للتسليم المؤسسي (P0)

- اختبار دورة كاملة غير مدمر: فاتورة طالب، تحصيل جزئي، ذمم، قيد، أستاذ، تقرير، إلغاء، ثم إعادة تحميل والتحقق من الأثر.
- اختبار تزامن يثبت عدم إنشاء قيد مكرر عند إعادة إرسال نفس العملية أو وصول طلبين متزامنين.
- اختبار إقفال الفترة من الخادم وقاعدة البيانات، مع منع الترحيل وإعادة فتح موثقة بصلاحية وموافقة.
- مصفوفة صلاحيات فعلية لفصل الإعداد، الإدخال، الاعتماد، الترحيل، والعكس؛ الواجهة وحدها لا تكفي.

### نواقص عالية الأولوية (P1)

- مطابقة بنكية باستيراد كشف، قواعد مطابقة، فروقات ورسوم، وتسوية معتمدة.
- ذمم الطلاب: جدول أقساط، تحصيل جزئي، منح وخصومات، مرتجعات، إشعارات، وتسويات.
- مشتريات وموردون: طلب شراء، أمر شراء، استلام، فاتورة، مطابقة ثلاثية، دفعة، وإشعار دائن.
- ربط الموازنة بالالتزامات وأوامر الشراء وحدود الصرف قبل إنشاء سند الدفع.
- تعدد الدفاتر والعملات وإعادة التقييم والترجمة عند وجود أكثر من عملة تشغيلية أو معيار.
- توحيد الفروع والاستبعادات بين الشركات/الفروع، إن كان النطاق يتطلب مجموعة مدارس.

### نواقص متوسطة (P2/P3)

- مركز تقارير ذاتي مع تصدير PDF/XLSX رسمي ومعلومات مصدر واضحة.
- مرفقات موثوقة قابلة للمعاينة والتنزيل للأصول والسندات، بدل حالات «غير متاح حتى ربط التخزين».
- مؤشرات تشغيلية منشورة: فشل الترحيل، زمن الإقفال، نسبة المطابقة الآلية، ونسبة المعالجة اليدوية.
- تحقق بصري فعلي على شاشات الهاتف والشاشات الصغيرة؛ المراجعة النصية لا تثبت جودة العرض المرئي.

## 3. الفجوة مقارنة بالبرامج الاحترافية

النظام يقترب من طبقة الأستاذ العام المدرسية، لكنه لا يساوي بعد SAP/Dynamics/NetSuite في إدارة الخزينة، المشتريات، التسويات البنكية، الدفاتر المتوازية، التوحيد، وسير الموافقات المؤسسي. الفجوة ليست في عدد الشاشات بل في اكتمال دورة المستند من المصدر إلى القيد والتسوية والتقرير والإقفال.

## 4. الأدوات التكميلية

- الطباعة المباشرة للسندات وتقارير الأستاذ موجودة.
- التصدير كان يعلن Excel لكنه ينتج CSV؛ تم إصلاحه إلى XLSX حقيقي مع ورقة مجمدة ومرشح تلقائي وخلايا آمنة.
- قالب استيراد القيود موجود، لكن يلزم اعتماد/معاينة/تقرير أخطاء قبل الإنتاج.
- أزرار المحاكاة واختبارات الجهد مفيدة للتحليل، ويجب إبقاء وسمها واضحًا بأنها ليست حركات محاسبية.

## 5. المظهر والهوية

المكونات الحسابية تستخدم لغة بصرية متقاربة: بطاقات بيضاء، حدود رمادية، ألوان حالة ثابتة، RTL، وأزرار صغيرة كثيفة. توجد مؤشرات ازدحام يجب معالجتها قبل التسليم المرئي: كثرة التبويبات داخل بوابة واحدة، كثافة الحقول في القيود والأصول، وتكرار أشرطة الإجراءات. لا يمكن اعتماد الحكم النهائي على كسر الهوية أو عدم التذاحم دون تشغيل الواجهة على أحجام سطح المكتب والهاتف والتقاط صور مراجعة.

## 6. الإصلاحات المنفذة في هذه الجولة

1. تحويل تصدير التقارير من CSV مقنّع إلى ملف XLSX حقيقي باستخدام أداة جداول المشروع، مع تحرير URL المؤقت بعد التنزيل ومعالجة فشل التوليد.
2. تنظيم مسار تحديث مؤشرات لوحة الأستاذ بحيث يضبط حالة التحديث في `try/finally` بدل تركها عرضة للبقاء في حالة غير متسقة عند حدوث خطأ.
3. فحص الأنواع نجح عبر `npm run lint`.

## قرار التسليم

الحالة المقترحة: **تسليم تجريبي/UAT مشروط**، وليس اعتمادًا ماليًا إنتاجيًا نهائيًا. يلزم إغلاق اختبارات P0 أعلاه، ثم تنفيذ سيناريوهات UAT المعتمدة على بيئة اختبار منفصلة، وبعدها فقط يمكن اعتماد الوحدة للتشغيل المالي الكامل.

## نتائج المراجعة المباشرة عبر المتصفح

تم فتح النسخة المنشورة على المتصفح ومراجعة المسارات دون إنشاء أو ترحيل أو عكس أي حركة مالية.

- الاتصال الكانوني ظهر متصلاً، مع 4 قيود و0 سند قبض و0 سند صرف.
- القيود اليومية عرضت القيود الأربعة مع توازن المدين والدائن، وحمت القيود الكانونية من التعديل المباشر.
- سندات القبض والصرف ظهرت كنماذج كاملة، لكن لم تُنفذ عملية حفظ أو ترحيل.
- ميزان المراجعة أظهر أرصدة صفرية رغم وجود القيود والإيراد الظاهر في لوحة المؤشرات بقيمة 601,405.00؛ هذا عيب اتساق تقريري، وتمت إضافة معالجة اشتقاق الرصيد من الحركات عند غياب رصيد مركزي مادي.
- شاشة الإقفال أعلنت الجاهزية مع إجمالي حركات مدين ودائن يساوي صفرًا، لذلك لا ينبغي اعتماد الإقفال قبل تصحيح مصدر الأرصدة وإعادة اختبار الشرط.
- شاشة الخزينة والبنوك عرضت فشل تحميل صريحًا بسبب عدم تأكيد التخزين الكانوني؛ هذه ليست شاشة تشغيلية جاهزة في النسخة الحالية.
- شاشة خرائط الترحيل أظهرت أن الربط يحتاج استكمالًا، رغم ظهور شارة «جاهز» في القائمة الجانبية؛ الشارة مضللة ويجب ربطها بالحالة الفعلية.
- ذمم الطلاب والموردون والأصول ظهرت بلا بيانات ضمن المدرسة المفحوصة؛ لا يمكن اعتبار دوراتها مكتملة دون بيانات UAT مرتبطة وإثبات دورة مستند.
- مرئيًا، لا يوجد تمدد أفقي في نافذة الاختبار (999×730)، لكن بعض الشاشات كثيفة جدًا، وإشعارات الحالة المتكررة تغطي أعلى المحتوى عند التنقل السريع.
