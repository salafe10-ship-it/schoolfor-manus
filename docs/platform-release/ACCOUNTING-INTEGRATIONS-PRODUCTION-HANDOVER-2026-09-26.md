# تسليمة الإنتاج — تكامل الحسابات العامة مع الرسوم وHR والمخزون

**تاريخ المراجعة:** 2026-09-26  
**البيئة:** `https://schoolfor-manus.salafe10.workers.dev`  
**الإصدار المفحوص:** `4a5b3b4d4573d0413fd0def3211a85fceb387ef7`  
**النطاق:** الرسوم الدراسية والتحصيل والذمم، HR (الرواتب والسلف والخصومات)، المخزون والمشتريات والمبيعات، وتتبّع الأثر حتى دفتر الأستاذ والتقارير.  
**القرار:** **NO-GO محاسبي — لا تعتمد دورة مالية إنتاجية بعد.**

هذا الحكم لا يطعن في نجاح نشر التطبيق أو في سلامة الضوابط البرمجية. النشر نجح، لكن بيانات الإنتاج وخرائط الترحيل والتسويات الحالية لا تحقق شروط تسليم محاسبي موثوق.

## حالة المعالجة البرمجية الحالية

تمت معالجة الفجوات البرمجية التالية في فرع التسليم، مع إبقاء القرار المحاسبي NO-GO إلى حين اعتماد بيانات وخرائط الإنتاج:

- إضافة مسار سداد فاتورة المورد كانونيًا ومقاومًا للتكرار، يقيد مدين الدائنين ودائن الخزينة/البنك ويحدّث الرصيد والتدقيق ذرّيًا.
- منع ترحيل حركة مخزون موسومة «بيع» إذا لم تحمل فاتورة بيع وسعر بيع وحساب إيراد؛ لا ينشأ قيد تكلفة منفرد مضلل.
- جعل شاشة الخرائط والكتابة المالية تعتمد readiness الفعلية، وإيقاف الكتابة عند غياب الخرائط الصحيحة.
- إضافة تتبع آمن للمصادر الكانونية غير القياسية في التقارير دون تحويلها شكليًا إلى سند قبض أو صرف.
- دعم مدفوعات الموردين في سجل المخزون كإسقاط موثق مرتبط بالقيد، مع تحقق الرصيد والمرجع وعدم تجاوز المتبقي.

## ما هو سليم تقنياً

- إصدار فاتورة رسوم، سند قبض، التخصيص على الفاتورة، التخفيض، العكس، والإثبات الكانوني لها مسارات خادمية ذرية ومقاومة للتكرار. لا تسمح الواجهة بمصدر محلي بديل عند غياب المصدر الكانوني.
- مسير HR يفصل اعتماد الموارد البشرية عن إثبات الالتزام ثم الصرف، ويعيد احتساب المسير على الخادم ويستخدم بصمة للبيانات المعتمدة. السلفة لا تصرف قبل اعتمادها، ويولد صرفها قيداً متوازناً عند توافر الخرائط.
- الاستلام المخزني وفاتورة المورد والحركات والجرد لها تحقق مركزي، ومطابقة ثلاثية، وإثبات كانوني مقصود بدلاً من اختراع رقم قيد في المتصفح.
- القيود المنشورة مرتبطة بمصدرها وقابلة للعكس بقيد تعويضي؛ لا يوجد حذف مباشر للقيد المرحل.

## موانع الاعتماد الإنتاجي (P0)

1. **خرائط الترحيل الإلزامية غير مهيأة.**
   في شاشة «خرائط الترحيل إلى دفتر الأستاذ» ظهر النص «الربط يحتاج استكمالاً» مع غياب حسابات جميع الخرائط الإلزامية: ذمم وإيراد الرسوم، الصندوق والبنك، مصروف والتزام الرواتب، سلف وخصومات الموظفين، وأصل المخزون وGRNI والدائنين وتكلفة الصرف والتسويات وضريبة المدخلات. هذا يمنع ترحيل أي معاملة جديدة بصورة صحيحة.

2. **القوائم المالية لا تتوازن.**
   لوحة الحسابات الحية تظهر فرق ميزانية موجباً مقداره 601,405.00 د.ل. لذلك لا يمكن اعتماد ميزان المراجعة أو قائمة المركز المالي أو صافي الدخل، ولا تصلح التقارير الحالية كأساس إقفال أو تسليم.

3. **حلقة الرسوم والذمم غير مثبتة ببيانات تشغيلية.**
   دفتر ذمم الطلاب الحي لا يعرض أي طالب، وسجل الحسابات يعرض 0 سند قبض. لا توجد عينة إنتاجية مؤكدة يمكن من خلالها مطابقة: فاتورة رسوم ← ذمة الطالب ← سند قبض ← تخصيص ← قيد ← تقرير/كشف حساب.

4. **مسير الرواتب سبتمبر 2026 غير قابل للترحيل.**
   المسير الحي في حالة «مسودة للمراجعة»، ويوجد تنبيه صريح: موظف نشط بلا عقد سارٍ للفترة. كما أن خرائط HR المحاسبية غير معتمدة، لذلك لا يجوز اعتماد المسير أو إثبات الالتزام أو صرفه.

5. **المخزون والمشتريات غير مهيأين تشغيلياً.**
   البيئة الحية تعرض 0 أصناف، 0 مستودعات، 0 تقييم مخزون، 0 طلبات شراء، 0 أوامر شراء، و0 التزامات موردين. أزرار الإنشاء والتحرير والطباعة والتصدير معطلة. لا توجد دورة GRN/فاتورة مورد/سداد أو جرد مثبتة يمكن ربطها بالأستاذ العام.

## فجوات وظيفية يجب معالجتها قبل التسليم الكامل

1. **المبيعات العامة للمخزون غير مكتملة محاسبياً (P1).**
   حركة النوع `sale` في المخزون العام تثبت فقط: مدين تكلفة الأصناف المصروفة / دائن المخزون. نموذج الحركة يطلب تكلفة الصنف ومرجعاً، ولا يلتقط سعر البيع أو العميل أو فاتورة بيع أو ضريبة مخرجات أو وسيلة تحصيل. لذلك لا توجد دورة عامة مكتملة: أمر بيع/فاتورة ← ذمم أو نقدية ← إيراد وضريبة ← تكلفة ومخزون.  
   ملاحظة: بيع الزي المدرسي له مسار مستقل يجمع الإيراد والتكلفة، لكنه لا يغطي مبيعات المخزون العام.

2. **سداد فواتير الموردين غير موصول بترحيل مركزي آلي (P1).**
   دورة المورد تثبت عند اعتماد الفاتورة: مدين GRNI وضريبة مدخلات / دائن الدائنين، ثم تحيل السداد إلى الخزينة فقط. قائمة مصادر مزامنة المخزون لا تتضمن `vendorPayments`، ولا يوجد رابط إلزامي بين دفعة المورد وسند صرف/قيد خزانة/تحديث تلقائي لرصيد AP. يلزم تنفيذ ذلك كعملية واحدة ذرية أو وضع العملية في وضع الحظر.

3. **التتبّع من التقرير إلى جميع المصادر ناقص (P1).**
   شاشة التقارير تتنقل إلى سند قبض أو سند صرف، لكنها لا تفتح فاتورة الرسوم أو مسير الرواتب أو مستند المخزون/GRN/فاتورة المورد من القيد نفسه. التسليم الاحترافي يتطلب Drill-down موحداً: تقرير ← حساب ← قيد ← مستند المصدر ← سجل التدقيق.

4. **تضارب حالة الواجهة (P1).**
   الشريط الجانبي يعرض «خرائط الترحيل المحاسبي — جاهز»، بينما الشاشة ذاتها تؤكد أن الربط يحتاج استكمالاً وتعرض جميع الخرائط الإلزامية كغير مهيأة. يجب أن تعتمد الشارة على نتيجة readiness الفعلية، وأن تمنع وصف الوحدة بأنها مرتبطة/جاهزة قبل تحقق الخرائط والفترة المفتوحة.

5. **أدوات التصدير في المخزون غير متاحة في الحالة الحية (P1).**
   أزرار PDF وExcel والطباعة معطلة. بعد تهيئة البيانات يجب أن تكون متاحة للتقارير الموثقة فقط، وتصدر نطاق الفلترة ووقت الإصدار والهوية ومصدر البيانات.

## خطة الإقفال والقبول

لا تنفذ معاملات مالية حقيقية قبل إغلاق البنود التالية بالترتيب:

1. اعتماد شجرة حسابات إنتاجية وفترة مالية مفتوحة، ثم تعيين كل خريطة إلزامية إلى حساب فرعي نشط بطبيعة صحيحة.
2. تصحيح القيود/الأرصدة الحالية أو عكسها وفق سياسة معتمدة، ثم إعادة بناء ميزان مراجعة متوازن بحيث: الأصول = الخصوم + حقوق الملكية.
3. إجراء UAT غير مدمر لدورة طالب واحدة: إصدار فاتورة تشمل خصماً/ضريبة عند الاقتضاء، سند قبض جزئي، تخصيص، تقرير ذمم، عكس مضبوط، وإعادة مطابقة القيد والتقرير.
4. ربط عقد الموظف الناقص، ثم اختبار مسير رواتب صغير: اعتماد HR ← التزام ← صرف ← تسوية قسط سلفة وخصم، مع مطابقة حساب التزام الرواتب وذمم السلف والخصومات.
5. تحميل بيانات مخزون تجريبية معتمدة واختبار: PO ← GRN ← فاتورة مورد ← سداد خزانة ← جرد/تسوية ← صرف/بيع، مع التحقق من المخزون وGRNI وAP وضريبة المدخلات وCOGS.
6. تنفيذ أو حظر مبيعات المخزون العام وسداد الموردين إلى أن يصبح لكل منهما مستند مصدر وقيد تلقائي ومعرّف ربط ومراجعة عكس.
7. تشغيل UAT كامل مع أدلة مرفقة، ثم إعادة فحص الجاهزية والتقارير والتصدير. يعتمد التسليم فقط إذا كانت الخرائط مكتملة، التقارير متوازنة، وجميع الدورات تثبت روابطها في الأستاذ العام.
